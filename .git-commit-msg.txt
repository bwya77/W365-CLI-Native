Fix WSL sign-in truncating the OAuth URL at "&", dropping client_id

The WSL browser-launch fix in v0.5.2 built the cmd.exe command line via
ProcessStartInfo.ArgumentList, which quotes each argument with normal Win32 argv
rules (only wraps in quotes if it contains a space). cmd.exe re-parses whatever
raw command line it receives using its own separate rules, where an unquoted "&"
is a command separator -- so the OAuth authorize URL (full of "&"-separated query
parameters) got silently truncated at the first "&", dropping whatever parameter
happened to land after it. Depending on MSAL's parameter ordering that was
client_id, producing "AADSTS900144: The request body must contain the following
parameter: 'client_id'." Now builds the raw Arguments string ourselves with the
URL explicitly wrapped in double quotes, which keeps cmd.exe from splitting it.
Verified directly against cmd.exe with a synthetic multi-"&" URL: unquoted lost
everything after the first "&" (cmd.exe tried to run "redirect_uri=..." as its own
command and failed), quoted preserved the full string intact.
